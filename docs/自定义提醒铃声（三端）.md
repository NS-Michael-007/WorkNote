## 一、统一设计（三端同一套思路）

| 决策 | 内容 | 原因 |
|---|---|---|
| 存副本，不存外链 | 用户选中的音频复制进应用私有目录，只保存副本路径 | 原文件被删、被移动到别的文件夹、SD 卡拔掉都不会导致到点没声音 |
| 通知渠道本身静音 | Android 新建 `task_alert_v2` 渠道，`setSound(null, null)`、不震动 | Android 渠道建立后声音不可改，只能换渠道 id；不静音会出现"系统默认音 + 自定义音"叠响 |
| 出声由代码层播放器负责 | Android 用 `MediaPlayer`、iOS 用 `UNNotificationSound(named:)`、鸿蒙用 `AVPlayer` | 用户自选音频不受系统渠道音约束 |
| 粒度＝全局一个 | 三端都是"一个 App 一首"，不是每条便签不同铃声 | 与用户原话"增加响铃替换，拾取本地文件夹中的音乐"一致，且不动三端共享的数据契约 |

技术硬限制（平台给的，不是取舍）：

- Android：`MediaPlayer` 支持的格式宽（mp3/m4a/aac/wav/ogg/opus/flac/mid/amr），无时长限制。
- iOS：通知音**只认 wav / aiff / caf**，**最长 30 秒**，且必须放在沙盒 `Library/Sounds`。别的格式系统直接静音，不会退回默认音。
- 鸿蒙：通知提示音走系统，自定义音频由 App 自己的 `AVPlayer` 播放。

### 2.4 本轮**没**取到证的环节（必须说清楚）

1. **"到点真的响"没有证据。** 13:08 卡片弹出那一刻，`shared_prefs` 里 `notify_sound=false`（「提醒时响铃」开关处于关闭状态），`Alerts.fire()` 第一行 `if (AppSettings.notifySound(context)) playSound(context)` 直接跳过，所以没出声是对的、不是 bug。同时 `dumpsys audio` 的 `players:` 段里 **uid 10292 一条 `AudioPlaybackConfiguration` 都没有**，这正好反证"当时没有播放"。
   - 现在三个开关已全部打开并复核：`notify_sound=true`、`notify_vibrate=true`、`notify_screen_on=true`、`exact_alarm=true`。
   - 还差的就是**一次在开关打开状态下到点、并且人耳听到自定义音**这一步。
2. **第二条测试便签被删掉了。** 13:15:00 那条「铃声联调测试」在 `notes` 表里状态变成了 `DELETED`、`remind_count=0`；`ReminderReceiver` 开头有 `if (!note.isActive) return`，所以 13:15:00 闹钟虽然排上了但被跳过了。同时手机上打开的编辑页里出现了「公司车辆 / 上线年检 / 1月22日」这类不在工程里、也不在数据库里的内容，说明**这段时间有人在手机上手动操作**（删掉了那条测试便签）。因此我没有继续用脚本点屏幕，避免误删/误保存别人的草稿。
3. 免打扰（DND）期间是否出声未定：`AudioAttributes.USAGE_NOTIFICATION` 在 DND 下通常被系统静音，要不要改成 `USAGE_ALARM` 还没拍板。
4. 铃声是"全局一个"还是"每条便签各一首"：当前按全局一个实现，若要按便签区分需改三端共享契约里的数据模型。
