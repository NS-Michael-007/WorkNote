## 三、密钥怎么存（推荐顺序）

1. **本地（首选）**：`keystore/worknote-release.jks` + `keystore.properties` 一起，压缩成带密码的 7z/zip 放到 U 盘或另一台机器；或放到自己手机的文件保险箱。密码单独记在别处（纸质/密码管理器），不要和压缩包放一起。
2. **GitHub（只放私有仓库，且只放 Secrets）**：把 jks 转成 base64 存进仓库的 **Settings → Secrets and variables → Actions**，例如 `KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`。CI 里解码成临时文件再构建，产物上传到 Release。**不要把 .jks 和明文密码一起提交进仓库**——私有仓库一旦转公开、或者误拉协作者，等于密钥泄漏，谁拿到都能签一个"你的应用"覆盖安装。
3. 不要用公开仓库托管密钥，也不要贴到任何在线粘贴板。

## 四、三条铁律（会踩死人）

1. **这套密钥丢了，现有安装就无法升级**：Android 只允许"同签名、包名相同、版本号递增"的覆盖安装。密钥丢了只能换新密钥，代价是所有用户（包括你自己）必须先卸载旧版，**数据库会一起被清空**。
2. 因此从现在起，正式发版一律用这个 jks 签名；debug 包只用于开发调试。
3. 备份至少两份，两份放在不同介质上。

## 五、从 debug 包切到 release 包（现在这一步怎么操作）

debug 包和 release 包签名不同，直接 `install -r` 会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。手机上现在装的是 debug 包，切换必须**先卸载**，而卸载会清空 `worknote.db`（也就是你那条「接待客人」便签）。

安全切换顺序：
1. 打开 App →「我」页 → 数据备份 → **导出 .taskbak**（落在 `下载/工作便签提醒/`）。
2. 卸载旧包：`adb uninstall com.workspace.worknote`。
3. 安装新包：`adb install -r "app\build\outputs\apk\release\app-release.apk"`。
4. 打开 App →「我」页 → 从备份恢复，选刚导出的 `.taskbak`。

以后固定用 release 包升级，就不再有卸载清数据的麻烦——只要版本号往上加，直接 `install -r` 覆盖即可。

## 六、以后每次发版

1. 改 `app/build.gradle.kts` 里的 `versionCode`（每次 +1，必须是整数递增）和 `versionName`（如 `1.0.1`）。
2. 跑 `assembleRelease`。
3. 把 `app-release.apk` 重命名成 `WorkNote-1.0.1.apk`，连同 `docs/` 一起传到 GitHub Release。
4. 记一下发版前的 `git tag`（如 `v1.0.1`），方便回溯。

## 七、可选：把签名接到 GitHub Actions（只在私有仓库做）

大致流程（供以后需要时参考，本次未配置）：
1. `keytool -importkeystore` 或 `base64` 把 jks 转成单行文本，存入 Secrets。
2. workflow 里 `echo "$KEYSTORE_BASE64" | base64 -d > app/keystore.jks`，再写一份临时 `keystore.properties`。
3. `./gradlew assembleRelease`，用 `softprops/action-gh-release` 上传 APK。
4. 结束后删掉临时密钥文件（runner 用完即弃，不留痕）。
