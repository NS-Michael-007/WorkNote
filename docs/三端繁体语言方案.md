# 三端繁体中文（繁體中文）落地说明

记录时间：2026-11-08。本轮要求是「三个软件都添加一份繁体语言」，iOS 与鸿蒙的取法由助手直接定，用户只确认。

## 一、三端统一的语言档位

三端设置项里都提供同样的四项，存的值也统一，方便以后写设置迁移：

| 界面显示 | 存的值 | Android Locale | iOS 写进 AppleLanguages | 鸿蒙 setAppPreferredLanguage |
| --- | --- | --- | --- | --- |
| 跟随系统 | `system` | 不指定 | 删除该键 | 不设置 |
| 简体中文 | `zh` | `zh-CN` | `zh-Hans` | `zh-Hans` |
| 繁體中文 | `zh-Hant` | `zh-TW` | `zh-Hant` | `zh-Hant` |
| English | `en` | `en` | `en` | `en` |

`zh-Hant` 是脚本位（不是 `zh-TW` 的地区位），这样台湾、香港、澳门的系统语言都能命中同一套繁体资源，不用维护三份。

## 二、Android（已完成，真机验证过）

改动：
1. 新增 `app/src/main/res/values-b+zh+Hant/strings.xml`，**201 条**，与 `values/strings.xml` 一一对应（键集合完全相等，`%1$d` / `%1$s` 占位符顺序一致）。
2. `AppSettings.kt` 增加 `LANG_ZH_HANT = "zh-Hant"`；`localeFor()` 返回 `Locale.TRADITIONAL_CHINESE`。
3. `ProfileFragment.kt` 的语言对话框由 3 项变 4 项；`languageLabel()` 同步支持繁体。
4. 顺带把 `BackupManager.kt` 里 6 条**写死的错误文案**抽成字符串资源（导出失败/导入失败会直接把这几句显示给用户），并让 `fromJson` 接收 Context，`title` 缺省值改用 `R.string.unnamed_note`；`values` / `values-en` / `values-b+zh+Hant` 三份同步补齐。
5. `values/strings.xml`、`values-en/strings.xml` 各加一条 `lang_zh_hant`。

证据：
- 构建：`gradlew.bat assembleDebug` **BUILD SUCCESSFUL**；`app-debug.apk` 由 7,045,344 字节变为 **7,059,024 字节 @ 2026/11/08 12:37:07**（多出 40,880 字节，就是繁体资源表）。
- 资源表：`aapt2 dump resources app-debug.apk` 里 `string/lang_zh` 出现 `(b+zh+Hant) "簡體中文"`、`string/lang_zh_hant` 出现三档值，证明繁体配置真的被打进包，不是只加了目录。
- 真机（realme RMX5080 / Android 16 / 序列号 （已隐去））：
  - 切到「繁體中文」后主界面标题变「主介面」、空态变「還沒有便籤，點右上角 ＋ 新增一則」、Tab 变「主介面 / 日程 / 我」；
  - 「我」页整页繁体：強提醒權限（必須全開）、懸浮視窗權限、忽略電池最佳化、通知權限、鬧鐘與提醒（精確鬧鐘）、介面與顯示、背景圖、深色模式、字體大小、語言 → 繁體中文、便籤文字翻譯；
  - 「日程」页日期行变「1 號 週日」……「12 號 週四」；
  - 语言对话框自身也变繁体（標題「語言 / Language」，选项「跟隨系統 / 簡體中文 / 繁體中文 / English」）。
- 回切验证：切到 English 后主界面变「Notes / Schedule / Me」、空态英文；再切回「跟随系统」恢复「主界面」，说明四档互换没有把资源表搞乱。

## 三、iOS（文案已就位，编译未验证）

做法：不逐个改视图，改用「键＝简体原文」的本地化表，SwiftUI 的 `Text("简体原文")` 会自动查表；表里没有的语言自动回落开发语言。

- 新增 `ios-app/Resources/zh-Hans.lproj/Localizable.strings`（恒等表，作兜底）、`zh-Hant.lproj`、`en.lproj`，三份各 **98 条**。
- 键覆盖已校验：从 `ios-app/Sources` 里提取的 **95 个唯一中文字面量**全部在表里，无遗漏；另有 `繁體中文`、`切换语言后需要重新打开 App 才会生效` 两条新增键。
- `SettingsStore.Language` 增加 `case zhHant = "zh-Hant"`，并新增 `applyLanguageToSystem()`：写入/清除 `AppleLanguages`，返回「是否真的改了语言表」。
- `ProfileView` 的语言选择器加 `.onChange` 调 `applyLanguageToSystem()`，下方加提示「切换语言后需要重新打开 App 才会生效」——iOS 不允许运行期换主语言，必须重启。
- `project.yml`：`INFOPLIST_KEY_CFBundleDevelopmentRegion: zh-Hans`，让系统语言不在三套表里时回落简体，而不是回落英文。

未验证项（不要当成已完成）：
- 三份 `.strings` 只做了静态检查（98 条解析、每行以分号收尾、键覆盖 100%），**没有跑过 `plutil`/编译**；
- `INFOPLIST_KEY_CFBundleDevelopmentRegion` 在 `GENERATE_INFOPLIST_FILE` 下是否生效，要等 CI 第一次构出 Info.plist 才能确认；
- `Text(lang.titleZh)` 传的是 `String`（verbatim），语言选择器里的名字不会跟着翻译，这是已知取舍。

校验过的东西（都是静态的，不含编译）：

- `Index.ets` 里 `$r('app.string.*')` 引用的 17 个键全部存在；
- 9 个 `json5/json` 配置文件用 Node 的 `JSON.parse` 逐份解析，全部通过（严格 JSON 都能解析，JSON5 自然没问题）；
- 图标为真实 PNG，4,734 字节。

未验证项（重点）：
